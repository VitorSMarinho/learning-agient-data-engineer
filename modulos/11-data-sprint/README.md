# Módulo 11 — Data Sprint

## Objetivo

Segundo módulo de consolidação da trilha: integra infra (01), orquestração (02), pipeline (03),
extração (06), streaming (08) e observabilidade (09) num sprint com escopo definido por você
mesmo, simulando prazo real. Aqui o "mentor" é o subagente `engineering-software-architect`
revisando a decisão de arquitetura, não só o código.

## Pré-requisitos

Módulos 01-09.

## Conceitos-chave

- Definição de escopo sob restrição de tempo (o que cortar sem comprometer o essencial)
- Trade-off de arquitetura documentado e justificado, não só implementado
- Revisão de arquitetura como prática (não só revisão de código linha a linha)

## Recursos gratuitos

- Revisitar os recursos já listados nos módulos 01, 02, 03, 06, 08, 09 — este módulo é síntese, não conteúdo novo
- [ADR (Architecture Decision Records) — guia oficial do padrão](https://adr.github.io/)

## O que você vai construir

Um sistema de dado de escopo médio (ex.: pipeline de streaming com observabilidade e infra
como código, combinando pelo menos 3 módulos anteriores), com pelo menos um ADR (`docs/adr/`)
documentando uma decisão de arquitetura relevante e por que a alternativa foi descartada.

## Como é avaliado

Este módulo ainda não tem projeto prático detalhado. Quando tiver, será resolvido e submetido
via PR neste repo, revisado pela skill `revisar-modulo-agient` usando o subagente
`engineering-software-architect`.
